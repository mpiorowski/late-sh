- **On any Brogue CE version bump**, re-pin `upstream-brogue/` (§3) and bump the `door-brogue` image tag. ## 1. Summary [STABLE]

Brogue runs the **real upstream Brogue CE curses binary on a PTY**, but **not** inside late-ssh. It lives in its own crate/pod, `late-brogue`, a minimal russh **server** that spawns one `brogue` child per SSH session. late-ssh reaches it exactly like the DCSS door reaches `late-dcss`: the door is a russh **client** that streams the remote terminal through a `vt100::Parser` and blits it into a ratatui widget below the top bar. SSH *is* the transport; there is no custom IPC.

The door is a deliberate near-clone of the DCSS door (built per DOOR.md's "reuse the shape almost verbatim" call), with three Brogue-specific divergences:

- **Identity is a per-player working directory, not a name flag.** brogue has no `-name`: it opens every player file (saves `*.broguesave`, recordings, high scores, run history, `keymap.txt`) relative to its cwd. The host therefore runs each child with cwd `LATE_BROGUE_DATA_DIR/players/<playname>` (created on demand; `host.rs::player_dir`), the same model dgamelaunch servers use. Saves AND high scores are per player; nothing is shared between players. That shape reaches into the log pipe below: the run-history line carries no player name, so the file's own path is the identity.
- **The hangup-save is ours.** Upstream's curses build dies unsaved on SIGHUP (only the SDL window-close path auto-saves). The `brogue-build` stage (`docker/doors/brogue.Dockerfile`) applies `scripts/brogue_hangup_save.patch`, which installs a SIGHUP/SIGTERM handler running upstream's own prompt-free `quitImmediately()` save path (flush recording, write the suspend `.broguesave`, `_exit`). Verified by starting a game on a PTY, SIGHUPing, and finding the save on disk. Everything downstream (the host's SIGHUP-then-SIGKILL teardown, the pod's SHUTDOWN_GRACE drain) relies on this patch; re-verify it on Brogue CE version bumps.
- **The victory-logging fix is ours too.** Upstream 1.15.1 gates the victory path's run-history write on `mode != EASY && mode != NORMAL` (the death path correctly tests `!= EASY && != WIZARD`), so ordinary wins are never logged while wizard wins are. `scripts/brogue_victory_log.patch` flips that condition to match the death path. The award pipe reads the run history for the Escaped/Mastered badge pair, so this matters twice over: normal wins must land, cheat wins must not. The Dockerfile asserts it fail-closed by grepping that `GAME_MODE_NORMAL` (which appears exactly once in `RogueMain.c`, on the buggy line) is gone after the patch.

Core shape (all inherited from the DCSS door; its CONTEXT §1 applies):
- `Screen::Brogue` has no top-level number key; it is reached by selecting the Brogue card in the Games hub (page `3`, after DCSS) and pressing `Enter`, which constructs the `State` (`enter_brogue`) and `connect`s in one step.
- One per-session `BrogueProcess` (russh client; twin of `door::dcss::proxy::DcssProcess`) owns the bridge task, the shared `vt100::Parser`, and the `ProxyStatus` flag.
- **Identity vs authorization split:** the connection authenticates with the Ed25519 key both ends derive from `LATE_BROGUE_SECRET` (blake3 domain `late.sh/brogue/v1`); the account's **arcade handle** (shared claim-once flow in `door/arcade.rs`, same handle as NetHack/DCSS/Usurper) travels as the SSH username and, after `playname::sanitize`, becomes the player-directory name. The handle is immutable once claimed, so a rename can never orphan a save directory.
- The child is spawned with `env_clear()` + allowlist (`TERM` via the host's `effective_term` fallback, `HOME` = the player dir, `COLORTERM=truecolor`). No locale vars: the curses build renders pure ASCII (`glyphToAscii`, plain `-lncurses`). `LINES`/`COLUMNS` are deliberately NOT exported (ncurses would freeze at spawn-time geometry); the pty winsize (openpty + TIOCSWINSZ on `window_change`) is the only size source. No CLI args at all: players cannot pass flags, so wizard mode is unreachable from the command line (it remains reachable from brogue's own main-menu mode picker; see §9 on awards).
- **Truecolor out, black keyed out.** `COLORTERM=truecolor` selects term.c's 24-bit path (exact `48;2;r;g;b` per cell instead of 6x6x6 cube coercion), preserving brogue's color gradients. Brogue paints every cell an explicit color and never emits the terminal default, so `render.rs::clear_canvas_black` maps background `Rgb(0,0,0)` (and `Indexed(16)`, cube black, for a host still on the 256 path) to `Reset` after the blit; the late.sh theme background shows through empty space, matching how NetHack/DCSS default-background cells render.
- **Fixed grid, pinned top-left, door area reset.** Brogue's grid is a fixed 100x34; it announces it with one `ESC[8;34;100t` at startup, which vt100 drops by default, so `proxy.rs::HonorResize` implements the resize callback and shrinks the parser to match. That makes Brogue the only door whose grid does not fill its viewport, so it is the only one where the anchor is visible: `render.rs::grid_rect` pins the grid to the viewport's top-left like every other door blits, clamping to a smaller viewport, and the slack falls to the right and bottom edges. `reset_door_area` clears the whole door area first so that slack shares one canvas (`Reset`) with the keyed-out interior. `Reset` is the app background rather than a bare terminal default: `app/render.rs` pushes `OSC 11` to set the terminal's own default background to `theme::BG_CANVAS()` whenever the user has the background color enabled.
- **ANSI black is keyed too (BCE).** ncurses' startup clear runs `ESC[2J` while SGR 40 is active, and vt100 erases with the current attributes, so every cell brogue never repaints carries bg `Indexed(0)`, which terminal themes often tint blue-gray (this rendered as a gray frame around the game before it was keyed). `clear_canvas_black` therefore maps `Indexed(0)` alongside `Rgb(0,0,0)`/`Indexed(16)` to `Reset`.
- **HVP normalized to CUP before parsing.** term.c's 24-bit renderer (`buffer_render_24bit`) positions the cursor exclusively with HVP (`ESC [ r ; c f`), which the `vt100` crate does not implement: it drops the move and the whole frame smears sequentially across the grid (the 256-color path never hit this because ncurses positions via CUP, `ESC [ r ; c H`). `proxy.rs::HvpNormalizer` rewrites the `f` final byte to the semantically identical `H` before `parser.process`, carrying split-sequence tails across SSH chunks. The root cause is pinned by `proxy_test.rs::vt100_drops_hvp_without_normalizer`: when a vt100 upgrade makes that test fail, HVP is supported upstream and the normalizer can be deleted.
- While Running, raw client bytes are forwarded (minus mouse/paste noise, `strip_input_noise`, and with the cursor keys retyped to match the game's current cursor-key mode, `keys_for_game` → `app/door/keys.rs`); `F1` is remapped to brogue's own `?` commands/help menu, and `` ` `` **detaches**: the game keeps running (state + SSH connection survive `set_screen`) while the backtick workspace cycle hops to the next live dungeon or back to chat; resume from the hub card or the cycle. A running game with no forwarded keystroke for 20 minutes is closed by the client (`IDLE_SHUTDOWN` in `state.rs`), landing as the host's SIGHUP-save; an off-screen non-running state is reaped in `app/tick.rs`. Ctrl-C arrives as a plain key (brogue runs curses `raw()` mode and the pty's ISIG never fires from the client side); `S` saves, `Q` abandons.
- **Teardown SIGHUP-saves** (via our patch): client disconnect or host SIGTERM with a live child sends SIGHUP, 5s grace, SIGKILL backstop; pod SIGTERM broadcasts a `watch` channel and `main.rs` holds the process for `SHUTDOWN_GRACE` (8s).
- **The log pipe (boards, badges, feed events — no screen scraping).** Brogue appends one TAB-separated line per finished game to `BrogueRunHistory.txt` inside the player's own directory: `seed, epoch, result, killedBy, score, gold, lumenstones, deepestLevel, turns` (upstream `saveRunHistory`), plus a `Reset` marker line when a player resets their in-game stats. The host serves those over the reserved `late_stats` SSH username (`late-brogue/src/stats.rs`, the late-nethack/late-dcss twin): the client pushes per-file byte offsets in env requests (`LATE_DOOR_STATS_CURSORS`; the set grows with the player count, so it is split across several requests the host concatenates), the host streams `<file-id>\t<offset>\t<line>` frames with tail -f semantics and stays stateless. Two Brogue-shaped differences from the other doors: there is no single log file, so the tailer rediscovers `players/*/` every poll pass and uses the frame id `players/<handle>/BrogueRunHistory.txt` as both the cursor key and the identity (`ingest/brogue.rs::playname_from_file`); and **only the standard variant's file is streamed** — Rapid and Bullet Brogue write their own variant-prefixed files in the same directory, and variant games do not count on the boards (owner decision 2026-08-08), so those files are never opened. late-ssh's ingestion task (`app/door/ingest/`: `brogue.rs` pure parser, `svc.rs` orchestration spawned in main.rs behind `LATE_BROGUE_ENABLED`, cursors in `door_log_cursors`) lands one `door_runs` row per finished game (`Escaped` → win, `Mastered` → mastery, `Died`/`Quit` → death/quit, depth = `deepestLevel`, already the run maximum so no milestone union is needed), idempotent via unique `(game, source_file, source_offset)`. From this pipe: the Brogue board triple on the Leaderboards page (Wins all-time counting escapes AND masteries, Deepest Dive, Top Score), the badge pair `BRE` (escape, 20k chips) and `BRM` (mastery, 50k) — the badge is once per account, the chips repeat once per ingested run behind a 7-day per-milestone lockout (SHOP.md Phase 6, migration 158) — each granting only itself, like every door milestone — and #lounge feed events for deaths (killer phrasing branches on upstream's own capitalization convention: a bare lowercase monster name gets "killed by a/an", a capitalized custom phrase is used as-is) and wins, freshness+recency gated so backfill never floods the feed. There is no mid-run milestone stream: Brogue writes nothing until a game ends, so `door_milestones` stays empty for this game. Easy and Wizard games write no run-history line at all (upstream self-polices, once our victory patch fixes the inverted condition), so the in-game mode picker cannot reach boards or badges.
- Brogue draws a fixed 100x34 cell UI; on smaller terminals ncurses clips the right/bottom edge (playable but cropped, no in-game warning). The launcher copy says "roomiest at 100x34". No late.sh-side size gate.

The door is gated by the `brogue_enabled` profile flag in `late-ssh/src/config.rs` (enabled in every current profile); when disabled, `connect` is a no-op and the launcher shows "Currently unavailable". The host pod is deployed unconditionally (the flag gates only the client).

### Client — `late-ssh/src/app/door/brogue/`

| File | Responsibility |
|---|---|
| `mod.rs` | Module declarations + framing comment. Declaration-only. |
| `proxy.rs` | `BrogueProcess`: per-session russh **client** to the host. Owns the bridge task (`run_bridge`), the shared `vt100::Parser`, the `ProxyStatus` flag, and the input/resize command channel; `ProcessConfig.playname` carries the arcade handle. Near-clone of `door::dcss::proxy`. |
| `identity.rs` | `derive_client_key(secret)`: the shared-secret → Ed25519 key derivation (blake3, domain `late.sh/brogue/v1`). Must stay byte-identical to the host's copy (KAT-pinned on both sides). |
| `state.rs` | Per-session `State` (+ `StateConfig` constructor input): launcher/running `Mode`, connection config, the optional `BrogueProcess`, last viewport `Rect`, the post-exit input grace, `connect`, `set_viewport`, `intercept_input` (F1→`?`), `forward_input`/`keys_for_game`/`strip_input_noise`, and `tick`. No award/milestone scraping: badges come from the log pipe. |

In-game help is brogue's own `?`. |

### Host — `late-brogue/` crate (standalone binary)

| File | Responsibility |
|---|---|
| `main.rs` | Tracing init, `Config::from_env`, ephemeral SSH host key, run the russh server. Broadcasts a shutdown `watch` on SIGTERM/SIGINT and holds the process for `SHUTDOWN_GRACE` so live games hangup-save. |
| `config.rs` | `Config`: `bin` (default `/usr/games/brogue`), `data_dir` (playground root, default `/var/lib/late-brogue`), `secret`, listen addr/port (default 2327), idle timeout. |
| `server.rs` | russh `Server`/`ClientHandler`: `auth_publickey` (compares key DATA; see the nethack CONTEXT §7 comment-field gotcha), `pty_request`, `env_request` (the stats cursors), `shell_request`, `data`, `window_change_request`, `channel_eof/close`. Holds `effective_term` (TERM fallback) and the `SessionHost` split: a game `PtyHost` for players, a `StatsHost` for the reserved `late_stats` username. |
| `stats.rs` | `StatsHost`: the log-streaming session for late-ssh's ingestion client. Rediscovers `players/*/` each poll pass, tails each player's `BrogueRunHistory.txt` (standard variant only), and frames `<file-id>\t<offset>\t<line>`. Stateless: no cursors, no parsing, no DB. `parse_cursors`/`frame_lines`/`valid_playname_dir` are unit-tested. |
| `host.rs` | `PtyHost`: the per-session PTY bridge (openpty + `env_clear` + `setsid`/`TIOCSCTTY` + XON/XOFF clear + TIOCSWINSZ + detached reader) plus the `StopReason` teardown (SIGHUP-save on `Teardown`, plain close on `ChildExited`) and `player_dir` (the per-player cwd). Same shape as late-dcss's `host.rs`. |
| `identity.rs` | `derive_client_key(secret)`, identical to the client copy. |

## 3. Config And Deploy [VOLATILE]

### Client (env → `Config` → `SessionConfig` → `App`)
- Client enabled/host/port are profile literals in `late-ssh/src/config.rs` (dev `service-brogue`, prod `late-brogue-sv`, port 2327); `LATE_BROGUE_SECRET` is the only env the client reads (must equal the host's).

### Host (`late-brogue` env)
- `LATE_BROGUE_SECRET` (required), `LATE_BROGUE_BIN` (default `/usr/games/brogue`), `LATE_BROGUE_DATA_DIR` (default `/var/lib/late-brogue`; the playground root = the PVC in prod), `LATE_BROGUE_LISTEN_ADDR`, `LATE_BROGUE_PORT` (default `2327`), `LATE_BROGUE_IDLE_TIMEOUT`.

### Binary sourcing: built from verified upstream source, Brogue CE 1.15.1
- Compiled in the `brogue-build` stage (`docker/doors/brogue.Dockerfile`, published as the ghcr `door-brogue` image the root Dockerfile pins) from the pinned GitHub tag tarball, SHA-256 verified fail-closed (`BROGUE_*` ARGs). Build: `make bin/brogue TERMINAL=YES GRAPHICS=NO RELEASE=YES` (curses-only, no SDL; RELEASE drops the `-dev` version suffix that brogue bakes into save names). Two source patches, `scripts/brogue_hangup_save.patch` and `scripts/brogue_victory_log.patch` (both in §1), each applied with its own fail-closed grep (`handleHangup` present; `GAME_MODE_NORMAL` gone); the stage also runs `scripts/brogue_verify_isolation.sh` (the §4 save-isolation assertions, ~0.2s) and asserts `--version` prints exactly `Brogue version: CE <version>`. Every grep and the script gate the `make`, so a source that fails any of them never produces a binary.
- The terminal build reads no data files (DATADIR only matters for graphics assets), so there is no read-only data tree: `/opt/brogue/brogue` is the whole install, symlinked to `/usr/games/brogue`.
- **A local copy of that exact source lives at `upstream-brogue/` in the repo root** (gitignored, alongside `upstream-lotgd/` and `upstream-adarkroom/`; the re-fetch command with the SHA-256 check is in `.gitignore`). It is pinned to the same tag and hash as the Dockerfile, so it is the authority for questions the door's behavior inherits from upstream, §4's save-isolation invariant especially. Read-only: we link nothing from it, and the only changes we make to upstream are `scripts/brogue_hangup_save.patch` and `scripts/brogue_victory_log.patch`. **Re-pin it in the same commit as any CE bump**, or it silently stops describing the running binary.

### Images / infra / CI
- `runtime-brogue` stage: `libncurses6` (the build links plain `-lncurses`, not ncursesw) + `ncurses-term`, `/opt/brogue`, the `/usr/games/brogue` symlink, `/var/lib/late-brogue` chowned to `late`. `base` gets the same binary for `dev-brogue` (compose `service-brogue`).
- `infra/doors.tf` (`brogue` entry, stamped out by the `infra/door` module): the RWO `brogue-save` PVC (2Gi, `prevent_destroy`) and the `late-brogue` Deployment (replicas **1**, kill-before-create, `terminationGracePeriodSeconds=30` > `SHUTDOWN_GRACE`, `brogue-save-seed` initContainer that only chowns the mount; the host mkdirs the player dirs itself) + the `late-brogue-sv` ClusterIP Service on 2327. The `brogue-identity-secret` (from the door module) is injected into both service-ssh and late-brogue.
- CI: `-brogue` releases route through `release.yml` to the generic `deploy_service.yml`: `ci` + `build`, then `kubectl set image deployment/late-brogue '*=<image>'` (covers the `brogue-save-seed` init container and the main container) and a rollout wait. No terraform runs on ordinary releases, so nothing else in the cluster is touched; when the `late-brogue` deployment is missing the run auto-bootstraps (a terraform apply `-target=module.door["brogue"]`). Other manifest changes go through `deploy_infra.yml`; terraform never reads or rewrites live image tags (deployments carry `ignore_changes` on images), so an ordinary release never rebuilds or restarts the door. Same rule as every other door. `doors.yml` (PR/weekly build-validate of `docker/doors/brogue.Dockerfile` via `docker/doors/smoke/brogue.sh`, publishes the pinned `door-brogue` image on main pushes at the tag pinned in the root Dockerfile, manual verify_deployed). License obligations tracked in `NOTICE`: **AGPL-3.0, and because we run a patched build, section 13 requires the corresponding source (pinned tarball + both our patches + build recipe) to stay publicly available while the door is hosted**; this repo is that offer.

## 4. Critical Invariants [STABLE]

Most of the DCSS door's invariants (§4 of its CONTEXT) apply verbatim: auth compares key DATA not the struct, `derive_client_key` byte-identical across crates (KAT-pinned), `env_clear` + allowlist, XON/XOFF off, close-channel-then-detach-reader, force `ProxyStatus::Closed` + wake render on close, all exits treated identically, fail-soft when disabled, `mod.rs` declaration-only, playname = the claim-once arcade handle, and the cursor keys retyped into the mode the game asked for rather than forwarded verbatim (`app/door/keys.rs`; brogue's `keypad(TRUE)` in `platform/term.c` puts it on the same footing as crawl, and an untranslated Up arrow reached brogue as ESC + `[` + `A`, i.e. cancel + "turn on autopilot?"). Brogue-specific:

- The playname keys the save **directory**, so `playname::sanitize` is a path-traversal boundary, not cosmetics: it must never let `/`, `.`, or any non-`[A-Za-z0-9_]` byte through, and a claimed handle row must never be deleted or reassigned (a re-claimed handle would open the dead account's saves). `arcade_handles` backs that up: unique on `lower(handle)`, and rows outlive their account (`ON DELETE SET NULL`, graveyard) precisely so a freed handle is never re-claimable. Since sanitize preserves case and only one case variant can exist, two accounts can never resolve to one directory.
- **The cwd is the only wall between players, and it holds because of an upstream input filter.** Every child runs as the same uid in one pod on one shared PVC: no chroot, no per-player uid, no seccomp, so `current_dir(&player)` in `host.rs` is the entire isolation story. It is sufficient today only because brogue gives a player no way to name a path (audited against the pinned source in `upstream-brogue/`, 2026-07-28):
  - The save/recording prompts substitute `-` for `/`, `\`, and `:` rather than rejecting them (`Recordings.c::characterForbiddenInFilename`, applied at `IO.c` in both the typed and clipboard paths), so `../someone/x` is saved as `..-someone-x.broguesave` in the player's own directory. `textEntryBounds` also clamps entry to printable ASCII.
  - The suffix is always appended (`snprintf("%s%s", name, GAME_SUFFIX)`), so every player-created file ends `.broguesave` or `.broguerec` and none can overwrite something brogue reads, `keymap.txt` included.
  - The load and recording browsers scan only the cwd: `listFiles` in `platform/platformdependent.c` does `opendir("./")`, non-recursive, with no parent navigation.
  - There is no shell escape: the game and platform sources contain no `system`, `popen`, `exec*`, or `fork`, and argv is empty.

  All four are asserted fail-closed at image build by `scripts/brogue_verify_isolation.sh`, run from the `brogue-build` stage right after the hangup patch (see §3). No Rust test can see these properties, so that script is the enforcement: a CE bump that relaxes any of them fails the build instead of silently opening every save directory to every player. **A failure there is never a reason to loosen the check**: re-audit the new source, and if a property genuinely moved, update the script and this section together.
- **Identity is asserted by late-ssh, not proven to the host.** The shared secret authorizes the *connection*; the playname is merely the SSH username, so anyone who can both reach the host and hold the secret can open any player's saves. That makes two things load-bearing rather than incidental: `late-brogue-sv` stays a ClusterIP off ingress and the ssh-tcp LoadBalancer (`infra/doors.tf`), and a leak of `LATE_BROGUE_SECRET` is a total identity bypass, so rotate it on both sides together.
- The hangup-save exists only because of `scripts/brogue_hangup_save.patch`. If a Brogue CE bump changes `curses-platform.c` or `quitImmediately`, re-verify the patch applies AND that a SIGHUPed mid-game child actually leaves a `.broguesave` behind; without it every rollout silently eats live runs.
- On teardown with a live child, SIGHUP before any SIGKILL so the run is saved; `PtyHost::Drop` must not abort the bridge task.
- Keep the child's argv empty. brogue's wizard/easy modes and seed control are runtime flags, and an empty argv is what keeps them unreachable for players.
- Don't add a late.sh-side terminal-size gate: brogue clips on small terminals without complaint, and the landing copy ("roomiest at 100x34") is the only messaging by design.

## 5. Tests And Verification [STABLE]

Root policy applies: agents run targeted tests via `make test-llm`; humans run the suite.

Inline `_test.rs` files cover: client+host `identity` (derivation determinism + distinctness + the cross-crate known-answer fingerprint pinning `late.sh/brogue/v1`), client `state` (disabled connect no-op, forward without proxy no-op, mouse/paste stripping, cursor keys following the game in and out of application cursor mode, F1 both encodings, exit grace, claim-prompt byte handling/caps/validation errors), shared `door/keys` (the CSI→SS3 rewrite, and what it must leave alone: plain keys, Page Up/Down, modified arrows, already-SS3 input, and a sequence cut by the chunk boundary), host `playname` (sanitize incl. traversal), host `server` (`effective_term` fallback), host `host` (`player_dir` distinctness), hub `state` (card order incl. Brogue), `primitives` (door screens outside the tab cycle).

The log pipe adds: host `stats` (cursor parsing over path-shaped file ids, line framing incl. embedded tabs and partial tails, and the playname-dir filter that keeps a frame-breaking or traversing directory name out of the stream), client `ingest/brogue_test` (real-shaped run-history lines for every result, the `Reset` marker, extra trailing fields, hostile/truncated lines, and the file-id → handle recovery incl. rejecting variant files), and `ingest/svc_test` (DB-backed: replay lands one row, escape and mastery each grant only their own badge and pay once for life, reset markers and foreign file ids advance the cursor without attribution). Board coverage rides `late-core/src/models/leaderboard_test.rs` (a Brogue escape plus a mastery both count on the wins board).

```bash
make test-llm ARGS="-E 'package(late-brogue) or (package(late-ssh) and test(brogue))'"
```

The §4 save-isolation properties live in upstream C source, so they are checked by `scripts/brogue_verify_isolation.sh` rather than by cargo: fail-closed in the `brogue-build` stage, and runnable by hand against the local reference with `scripts/brogue_verify_isolation.sh upstream-brogue`. Each of its five assertions was mutation-tested when written (weaken the property, watch the check go red); keep that habit when editing it, since an assertion that cannot fail is worse than none.

The PTY bridge and russh loops are process/network-bound and not unit-tested; verify launch/save/quit manually against a real host (compose `service-brogue`). The hangup-save path was verified by hand at build time (PTY + SIGHUP + save file present); re-verify on CE bumps.

## 9. Deferred / Future Work [VOLATILE]

- **Nothing reaps saves or recordings, and the PVC is 2Gi shared by every player.** Each finished game writes a recording (`saveRecordingNoPrompt` on death/victory) and a player can save unlimited games under distinct names, with no per-player quota and no cleanup job. Files are small, so this is slow rather than sharp, but it is unbounded and one player can fill the volume for everyone. Wanted: a host-side reaper (age out `.broguerec`, cap saves per player) and a PVC usage alert. **A reaper must never touch `BrogueRunHistory.txt`**: the log pipe's cursors are byte offsets into it, so truncating it rewinds ingestion (the host restarts that file from 0 on a shrink, and the client's idempotent inserts absorb the replay, but deleting it loses the tail entirely).
- **Harden the isolation instead of detecting changes to it.** Per §4, player separation still rests on upstream's input filter; the build-time script only guarantees we find out when that stops being true, not that players stay separated if it does. Running each child under a per-player uid, or giving it only the player dir as a writable mount, would make the boundary ours. Not urgent while the check holds, and the check is the cheap 90%, but a real boundary would not care what upstream does.
- ~~Awards from the per-player run history, not the screen.~~ **Shipped** (Phase 3, see §1's log pipe): the run history feeds chips, the BRE/BRM badges, the board triple, and the feed. The in-game mode picker is handled the way that item warned about: Easy and Wizard games write no run-history line at all, once `scripts/brogue_victory_log.patch` fixes 1.15.1's inverted victory condition. Re-check both on CE bumps.
- ~~No shared scoreboard.~~ **Shipped**: the Leaderboards page carries the Brogue triple, aggregated from `door_runs` rather than from the per-player high-score files (those are still per player and still unshared). Not surfaced on the door's own landing; do that if it is wanted.
- Brogue CE ships two official variants in the same binary (Rapid Brogue, Bullet Brogue) selectable from the main menu; they share the player dir and work today. **They do not count on the boards** (owner decision 2026-08-08): they write their own variant-prefixed run-history files and the stats host streams only the standard one. If we ever want them as separate cards, it is a `--variant` argv decision, which collides with the keep-argv-empty invariant; decide deliberately, and decide then whether their runs earn boards of their own.
- A lumenstone or deep-dive badge tier is still open. The run history carries both columns (`lumenstones`, `deepestLevel`) and they already ride into `door_runs.raw`, so it is a badge/reward-template decision, not a pipeline one.
- Per-user/global concurrency cap on the host pod if the envelope gets too loose (same posture as dcss: bounded 1:1 by late-ssh's conn caps today).
