# House Tables Context

## Metadata
- Scope: `late-ssh/src/app/lobby/house` — the fixed multiplayer "house tables" behind the Lobby modal (`Ctrl+G`), plus the five game runtimes (Poker, Blackjack, Asterion, Tron, Super Snake).
- Last updated: 2026-08-17 (Super Snake became perpetual: no match, no lives, no winner — one arena runs forever, players join and leave mid-flight, and each food is worth chips scaled by the moving-snake count. The seat's take is an in-memory tally that reaches the ledger once, when the seat is given up. The `ssnake_win` cooldown template is retired, migration 131)
- Parent context: `../CONTEXT.md` (the Lobby domain), then the root `CONTEXT.md`; read `../daily/CONTEXT.md` for the daily correspondence domain.
- Status: Active.

## 1. Summary

House tables replaced the demolished Rooms directory: one fixed table per game, no creation flow, no settings forms, no DB rows (the `game_rooms` table is dropped, migration 111). The Lobby modal (`Ctrl+G`) lists them in a fixed bottom section with live occupancy; Enter opens `Screen::HouseTable` (outside the Tab cycle, `q`/Esc back to the modal). A second stake tier later is a new `HouseTable` enum variant, not config.

Locked shape (owner decisions):
- Roster: Poker (1k stack, 10/20 blinds), Blackjack (10-chip stake), Asterion (the maze), Tron (quick speed + glitch mode), Super Snake (relaxed speed, 5 seats, perpetual self-shuffling arena).
- Everything is a closed enum + exhaustive match; no trait objects, no `_ =>` arms on the roster.
- House tables never touch the `daily_matches` correspondence model and have no DB rows of their own.

## 3. Runtime model

- **Singletons.** `HouseTableRegistry` holds `Arc<Mutex<Option<Service>>>` per variant; first enter creates the service with the variant's fixed settings and `HouseTable::table_id()` as its table id. Poker/blackjack/tron/ssnake singletons live for the whole process; Asterion keeps its stop-when-empty lifecycle (stopped singleton discarded and respawned on next enter, mirroring the old manager).
- **No persistence seam.** The rooms-era `Option<RoomsService>` fields and `sync_room_status`/`touch_room` calls were stripped in phase 3; the services publish watch snapshots and nothing else.
- **Chat + voice.** One permanent public `chat_rooms(kind='game')` row per variant (slug from the roster) plus an enabled `voice_channels(target_kind='chat_room')`, both ensured idempotently at startup (`ensure_chat_rooms`, called in `main.rs` before serving). Entering a table fires the idempotent `join_game_room_chat` from `App::tick` (membership is what makes the room and its voice channel appear in the user's chat snapshot). `kind='game'` keeps house chat off the Home rail, out of Mentions, and off IRC.
- **Activity.** Sit-downs ONLY (owner decision 2026-07-13, see the FRD): poker/asterion/tron/ssnake publish `RoomGameEvent::SeatJoined` onto the registry's shared channel; blackjack's `BlackjackEvent::SeatJoined` is translated by a forwarder; `start_seat_activity_task` turns those into `ActivityEvent::sat_down`. The runtimes publish NO other activity — their `game_won`/`game_played` emitters were deleted (quests are arcade-only, migration 110) and the services no longer hold an `ActivityPublisher`. Chip payouts were never event-driven: direct `ChipService` calls (asterion daily escape, tron cooldown payout, poker/blackjack settlements, and ssnake's one-per-visit `apply_move` write).
- **Chip balance sync.** `App::tick` reads `HouseTableClient::chip_balance()` into `App::chip_balance` and mirrors external balance changes in via `sync_external_chip_balance`, gated on `can_sync_external_chip_balance` — same contract the rooms backend had.
- **Kick / idle timeouts.** Two independent layers, owned per-game (not by the shared scaffolding):
  1. *Per-turn action timeout* (poker + blackjack only): `action_timeout_secs()` = 20s (`*/settings.rs`). Miss your turn and you're auto-stood/auto-folded (`schedule_action_timeout` → `auto_stand_remaining`). Stalls an active hand, not idle-sitting.
  2. *Seat idle timeout* (poker, blackjack, tron, ssnake): `SEAT_IDLE_TIMEOUT_SECS = 5 * 60`, except **ssnake, which uses 2 minutes** — its arena is always live and its seats are the scarce thing, so an untouched seat has to recycle fast. A generation-guarded self-cancelling timer — every meaningful action calls `touch_activity` → `record_activity`, which stamps `last_activity` and bumps a per-seat `activity_generation`, then arms a kick task that sleeps 5m and re-checks. If the generation changed or `last_activity.elapsed()` is under 5m the kick is a no-op, so the latest action always wins and stale timers evaporate. A pure sit-and-never-play (e.g. blackjack: no `pending_bet`/`bet`, never in `PlayerTurn`) falls through `kick_inactive_user` to the plain `SeatState::empty()` path and the seat reopens; tron also handles the idle-mid-race case (marks the rider crashed), and ssnake's kick routes through `leave`, which frees the seat outright. Ssnake's timer deliberately tracks keypresses, not motion: a steered-then-abandoned snake keeps slithering on its own, so only the idle timer reclaims its seat.
  - **Asterion has no idle kick** by design (`asterion/state.rs`): heroes die to the maze and an empty maze stops itself.
  - These timers are `tokio::spawn` + `sleep`, so like everything here they are in-memory and restart-lossy: a restart drops pending kick timers, and the next `touch_activity` re-arms them.

## 3a. Super Snake: the perpetual arena

Unlike every other table here, Super Snake has no match lifecycle. `SsnakePhase` is only `Idle` (nobody seated) or `Running` (the tick loop turning); there is no start key, no winner, no level picker, and no lives. Sitting down spawns you into the live board immediately; standing up frees the seat mid-flight. Eating an arena's last food reshuffles the board to a different random level and re-seeds everyone in place, so play never pauses. It is the only five-seat table (`MAX_SEATS = 5`, colours green/red/blue/purple/cyan) and its idle kick is 2 minutes rather than the usual five.

The level assets carry only `name`, `points-needed`, `tick-millis`, `initial-length`, `growth-factor`. The original `.LEV` keys `lives`, `lives-bonus` and `points-bonus` were deleted from every file and from the parser when lives went away — nothing parses and ignores them.

There are 55 arenas: the 20 ported from the DOS originals, 30 designed for the perpetual table, and 5 novelties (a SNAKE sign in walls, the same sign overlaid with a plus, a wall-free all-tunnel board, a solid cross whose quarters join only through the border tunnels, and a bumper field). `levels_test.rs` holds the two rules that make an arena safe to ship, and both are about the perpetual loop rather than aesthetics: **the floor must be one connected region on a torus** (food spawns anywhere and the arena only clears when the last food is eaten, so a sealed pocket wedges the table with no timeout to rescue it), and there must be **`5 x initial-length + 40` floor cells** so a full table fits. See the assets README before adding one.

- **Payout multiplier.** Every food and arena-clear payout is multiplied by `moving_snakes()` — seats whose snake is in `Motion::Moving`. `Idle` (never-steered) and `Dying` snakes count for nobody, which is what stops a table of parked idlers from inflating the rate. Rates live in `ssnake/settings.rs` (`SSNAKE_FOOD_CHIPS`, `SSNAKE_EDGE_BONUS_CHIPS`, `SSNAKE_BONUS_FOOD_MULTIPLIER`, `SSNAKE_BONUS_FOOD_ODDS`, `SSNAKE_CLEAR_CHIPS`, `SSNAKE_CRASH_CHIPS`, `SSNAKE_ARENA_FREEZE`, `SSNAKE_DEATH_SHRINK_PER_TICK`) and nothing else hard-codes a chip amount. Note `SSNAKE_BONUS_FOOD_ODDS` is an economy knob as much as a cosmetic one: at 1-in-10 with a 3x multiple it lifts the effective chip rate about 20% over a pink-free arena.
- **What a food pays.** One function, `settings::ssnake_food_chips(wall_edges, bonus_food, moving_snakes)`, owns the whole sum: base, plus `SSNAKE_EDGE_BONUS_CHIPS` per arena wall orthogonally touching the food (counted through the warp edges by `wall_edges`, cached in `food_wall_edges` when the food spawns), then the pink multiple, then the moving-snake count. Both the payout in `eat_food` and the number the UI advertises call it, so they cannot drift. The three food states read on two independent channels in `food_color`: hue says what it pays (gold plain, pink triple) and the pulse is reserved for the lap-ending food (`is_final_food`, which outranks pink). Pink deliberately does **not** blink — when both bonuses pulsed they were mistaken for each other, so a blinking cell now means one thing only.
- **Post-shuffle hold.** `advance_arena` arms `frozen_until` for `SSNAKE_ARENA_FREEZE` (4s — a clean second each for the 3/2/1/GO overlay drawn over the board). While it holds, `tick` still counts (so the food blinks and the countdown repaints) but moves nobody, and `steer` **drops** input rather than queueing it — the whole point is that a key pressed on the arena that just ended must not decide the first move on a level the player has not seen.
- **Death shrink.** `SSNAKE_DEATH_SHRINK_PER_TICK` (3) tail segments a tick, not the original's one: a long snake's wake otherwise locks its player out for roughly its own length in ticks, for a crash they have already paid for. Respawn length is `ssnake_respawn_length` — `SSNAKE_CRASH_LENGTH_PENALTY_PCT` (20%) shorter than the length it died at, floored at `SSNAKE_MIN_RESPAWN_LENGTH`. The original came back exactly as long, which on a big arena leaves an unwieldy snake unwieldy forever and the level unclearable; shedding a fifth per crash is what makes a long level recoverable. The chip penalty, not the length, is what makes crashing cost something.
- **Bailing out.** Standing up (`l`) while your snake is in `Motion::Moving` is charged `SSNAKE_CRASH_CHIPS`, same as hitting a wall. Without it `l` is a *free* crash-avoidance move: a snake one tick from a wall stands up, dodges the penalty, and sits straight back down on a clean distant spawn. `Idle` (never steered) and `Dying` snakes leave for free — the first was never at risk, the second has already paid. The idle kick passes `voluntary: false` and never charges, since it is involuntary and two minutes out, so it cannot be used to dodge anything. Note the related hole is already shut by other means: `drop_on_leave` is false for ssnake, so quitting the table screen or the SSH session does **not** free the seat — the snake keeps slithering unattended and crashes on its own.
- **Skip vote.** `v` casts a vote against the current arena; once every *seated* player has a live one, `vote_skip` reshuffles through the same `reshuffle_arena` path as a natural clear (new level, hold, votes cleared). Two guards make it a way out of a bad level rather than a way to shop for a good one: `SSNAKE_SKIP_COOLDOWN` (60s) between skips — load-bearing, because on a one-player table that player *is* the consensus — and `SSNAKE_SKIP_VOTE_TTL` (30s) per vote, so votes cannot accumulate across unrelated moments and hand a later voter a skip nobody is still behind. Any seat change also clears the tally, since it moves the bar the tally was counted against.
- **Sidebar sizing.** `draw_info_sidebar` renders an unscrolled `Paragraph`, so anything past the pane height is silently clipped with no indicator. Two things keep it readable. First, `preferred_height` asks for `max(arena_need, sidebar_height(state))` — and `sidebar_height` *builds the real lines and counts them* rather than tallying by hand, so it cannot drift from what is drawn. That count is only exact because every variable-length line (usernames, arena names) goes through `fit` to the sidebar width, so nothing wraps into an extra row; keep that up for anything added. Second, `CHAT_FLOOR` (6 rows) caps the ask, except when the arena alone needs more — the board always wins. Order is still by urgency (controls, roster, payout numbers, rules) so that a pane too short to hold everything loses the rules, which are also in the `?` guide.
- **Settlement (leave-only).** Food, arena clears and crashes move `PlayerState.chips`, an in-memory tally, and **nothing else**. The ledger is touched exactly once per visit, when the seat is given up: `leave` returns an `Option<Settlement>` and `ChipService::apply_move` writes it as `ssnake_arena_earned` (credit) or `ssnake_arena_lost` (debit, floored at zero, so a broke player simply is not chased). A seat that breaks even writes nothing at all. The sign picks the `ChipMove`; the amount is always positive.
  - **Why not per bite.** A bite is worth single digits and lands every few seconds per seat. Every `user_chips` write fires the migration-128 `chip_user_changed` notify, and the `ShopService` listener answers each one with a full `load_snapshot` (~8 queries, serialized in the one listener task that also serves flair and catalog updates for everyone). Per-bite settlement made a busy table the app's loudest DB producer and grew `chip_ledger` — which the monthly Top Chips board scans in full every 5 minutes — by orders of magnitude. One row per visit instead.
  - **The kick is a settle path, not an edge case.** `drop_on_leave` is false and nothing frees a seat when a session ends, so a player who closes their terminal is banked by `kick_inactive_user` two minutes later. It must keep returning its `Settlement`, or that player's whole visit is silently voided. `KickOutcome.reclaimed` is separate from the settlement because the kick timer is re-armed on every keypress: a stale timer firing against a live seat must neither publish nor write.
- **Spawn placement.** `spawn_cell` samples up to `SPAWN_CANDIDATES` free cells and keeps the one whose nearest rival *head* is farthest away by `torus_distance` (Manhattan across the wrapping arena). A joining player therefore lands in an empty pocket rather than on top of the pack.
- **Tick loop.** One loop per wake, generation-guarded like the old round loop, but it re-reads `tick_millis()` each iteration so an arena shuffle to a differently-paced level takes effect without a restart. It retires itself when the last snake stands up.
- **Chip feedback.** There is no chip event channel: the seat's running tally is already in the shared snapshot, so `State::pop_own_movement` diffs its own seat between two snapshots and pops the difference, labelled by `SsnakePlayerSnapshot.last_chip`. Up to three `+5` / `-10 crash` pops sit right-aligned on the arena's bottom border, expiring after `CHIP_POP_TTL` (2.5s); a food and the clear bonus land on one tick and therefore read as one pop (`+270 cleared`). The unbanked figure is shown per seat in the sidebar as `+120 **pending**` — never as a balance, because none of it is spendable until the player stands up. Ssnake's `chip_balance()` is `None` and `can_sync_external_chip_balance` is `true`: the arena is not an authority on anyone's balance, so the top-right counter stays the ledger's. A combo/streak multiplier would attach at `award`, which already names the movement.
- **Snapshot cost.** The watch publishes `Arc<SsnakeSnapshot>`. Every session that has opened this table keeps its client for the rest of the session (`drop_on_leave` is false) and `HouseState::tick` runs on every app tick regardless of screen, so a bare snapshot had every such session deep-copying five snake bodies at the arena's cadence to look at nothing. Same reason `LeaderboardService` publishes an `Arc`.

## 4. The blackjack event feed

The blackjack event channel is created eagerly in `HouseTableRegistry::new` (not lazily with the service), so its sender outlives every service instance. `forward_blackjack_seat_joins` subscribes lazily, inside `blackjack_service`'s `get_or_insert_with` on the first sit-down, and relays seat joins onto the shared seat-activity stream; the subscribe runs just before the `BlackjackService` that emits those events is constructed with the same sender, so no seat join can be missed.

## 5. UI surfaces

- **Lobby modal section** (`../modal_ui.rs`): a fixed `house tables` block at the bottom of the list — always five rows (stable chrome), name + tagline + occupancy (`empty` / `2 seated` / `2 seated · in round`) read from the singleton watch snapshots via `HouseTableRegistry::occupancy`. Enter opens the table; the entry rows are `LobbyEntry::House` appended after live games.
- **Screen::HouseTable**: outside the Tab cycle, entered only from the modal (or backtick). Chat-surface behavior comes from the two rosters in `app/input.rs` (`screen_has_chat_pane` + `embedded_chat_room_id`); the central gates there keep composing and chat overlays away from `house::input::handle_event`, so this module never re-checks them. Esc peels: selected table-chat message → close to modal. `compose_room_switch_allowed` stays Dashboard-only.
- **Backtick**: `GameWorkspace::HouseTable(HouseTable)` — tables where you hold a seat slot after the your-turn daily boards, roster order (`../workspace.rs::next_workspace`, unit-tested pure).

## 6. Known gaps / deferred

- Your-turn desktop notify (poker/blackjack) is edge-detected in `HouseState::notify_turn_edges` (every tick, off-screen included) against `HouseTableRegistry::awaiting_action(table, user_id)`, which reads the live singleton snapshots for ALL seated tables (not only the open client). Seeded silent on the first tick; asterion/tron/ssnake have no turn concept.
- No occupancy-driven repaint: modal occupancy is read per frame, which is fine at the render cadence.
- Table state is not durable across restart (accepted).
