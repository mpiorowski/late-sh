# Daily games: UI surfaces

The four places a correspondence match is drawn: the sidebar panel, the
lounge strip, the lobby modal and the board screen. Part of the daily games
domain (`CONTEXT.md`); per-game renderers are listed in `GAMES.md`.

## Sidebar panel (`panel.rs`)
- Fixed 6 rows: four match slots, one status line (`N open · entries/cap`), key hints (`` ctrl+g · ` toggle ``). Slots render dashes when empty; the panel never changes height between states (stable-chrome rule).
- Slot order is actionable > news > waiting: your-turn rows first (nearest deadline within), then unseen results (`you won` / `you lost` / `draw`, glowing in success/error/amber), then waiting rows. Since the cap (10) now exceeds the four slots, the panel is a deliberate **top-4 view**: the actionable/your-turn matches always win the slots and the tail (typically waiting rows, plus any overflow from unseen results) lives in the modal. Result rows still self-clear the moment the player looks (see §6).
- The panel has no title row: the sidebar's labeled separator rule (`── lobby ────`, built in `app/common/sidebar.rs::draw_panel_rule`) is the title. Every sidebar panel's rule is labeled this way; the lobby's label is the only one with an active state.
- Attention is split across two signals: the rule label glows while it's your turn in any match OR an unseen result is waiting (the sidebar computes this from `DailyState::my_matches`/`my_turn`/`my_finished`); the status line's open count glows while there are open challenges unseen since the modal was last opened (the liquidity signal; owned by `LobbyState`, passed into the panel as a bool). Own challenges never glow. `LobbyState::seen_open_ids` is seeded at session start so pre-existing challenges don't glow on login (result rows deliberately DO survive login: that persistence is their whole point).

## Lounge strip (`live_strip.rs`, `live_board.rs`)
- The strip itself is `app/live/` (`../../live/CONTEXT.md`): which source is featured, for how long, the frame, the key. What follows is what a daily match brings to it.
- Every active match is a candidate, the viewer's own included (`DailyState::live_candidates`), stamped with the row's `updated` (the claim, then every move). It keeps exactly the secrets the spectate board keeps even for a player: battleship shows the shots, never a ship, and the card games show what lies face up and a back for every card held, never a face in hand. `LiveBoard` carries no hidden card at all, so no renderer can leak one.
- Across replicas the pick holds because the snapshot does: every write that changes a `daily_matches` row fires `daily_match_changed` and every replica re-reads at once (§3), so a move made anywhere is on every strip within a notify's round trip, and the finish below is read off the snapshot rather than the `MatchFinished` event, so it is offered everywhere too. The one thing that stays on the writer's replica is the aim: `AimChanged` is in-process by choice, at eight a second it is the wire cost presence batches to avoid, and the cue is decoration. On another replica the featured pool match shows the rack without the stick and takes the strip on the shot, like every other move.
- Aims come off the existing `AimChanged` feed: every other player's aim is stored in `DailyState::live_aims` (pruned past `LIVE_AIM_WINDOW` each tick) and never marks the frame dirty on its own. While the strip draws a cue (`LiveState::aiming`) the #lounge card repaints on the half-tick edge, so a shooter sweeping the cue costs no extra frames beyond that.
- While an aim is fresh the table draws the guide under the balls and the cue stick over them, pulled back with the shot's pull, the `── now ──` rule glows, and the words read `eggy is lining up a shot`.
- Opening it goes through `open_board`, returning to the page it was opened from: read-only for a spectator, playable when it is the viewer's own. The hint reads `press o or click to watch` while a match is live.
- The finish is a snapshot transition, not an event: `note_results` runs when a snapshot lands and keeps every match in `finished_matches` that ended inside `LIVE_STAMP_HORIZON` (the row carries the winner, the result and the payout for `finish_headline`, the colours, and the position the match ended on: the finish writes the final state with the finished status in one update, so no active snapshot ever carries the winning move). Each is offered to the strip as `LiveSource::DailyResult`, stamped with `finished_at`, and joins the strip's Rest lane like a move (`../../live/CONTEXT.md` §0), showing `finish_headline` (`weslin won · eight ball · +400 chips`, chips named only when paid). The finished list drops a row once both players have seen the result, often a second after the finish, so a noted result stays in memory until the horizon passes; a result both players saw before this session's first snapshot is never noted. The payout is a second write behind the finish, so a noted result whose row is still listed re-reads its headline on each snapshot, and the chips appear on the line a notify later. A result opens nothing: its board is gone from the lobby, and the hint reads `press ctrl+g to play`.
- The words, one per picture row: players (with a colour mark each for backgammon and cribbage), `Chess · move 12`, a score (`Briscola · 34-21`, `Cribbage · 34-21 · hand 3`, `Backgammon · pips 167-160`, the snooker frame score; every pair challenger first, as the players read), what just happened (`eggy hit B7`, `eggy played A♥`, `eggy threw 9♦`; a gin hand that ended is named on the next deal, `eggy knocked · +14`, `eggy went gin · +31`, `eggy undercut · +27` or `dead hand, no score`, because the service deals the next hand in the same write and the knock itself is never on a live table), then the hint. The one-row form reads `8ball eggy v weslin`, `eggy is aiming`, or the result.

## Lobby modal (`modal_*`)
- Lives in `../modal_input.rs` / `../modal_ui.rs` (it fronts both game domains). Opened by reserved global `Ctrl+G` only (works anywhere, including while composing; pressed again it closes the modal). Opening calls `LobbyState::mark_seen`.
- Near-fullscreen: sized from the terminal minus a margin (8 cols / 4 rows), capped at 100x40 so lines stay readable on large terminals. The daily surface is a primary destination, not a peek.
- One scrollable list, `j`/`k`: your matches (unseen result rows first, `you won · checkmate` / `you lost · timeout` with an `enter view · x dismiss` hint, then active matches; Enter opens the board), then every open challenge (Enter claims with a confirm second-press; `x` cancels your own), then a `live games` section of other people's spectatable active matches (Enter opens the board read-only). The live-games header is hidden when there are none. Rows show the game and its chip prize (spectate rows show `challenger v opponent` + whose move it is instead). Result phrasing comes from `state.rs::result_phrase`.
- `c` opens the challenge picker: a small centered overlay on the modal with one row per roster game and its prize (`j`/`k` + Enter posts it open), so the roster scales without fighting the status line for width. `Esc` closes the picker, and confirm consumes its own first Esc.

## Board screen (`board_*`, `battleship_ui.rs`, `connect4_ui.rs`)
- `Screen::DailyMatch`, outside the Tab cycle, entered from the modal, the backtick cycle, or the #lounge live strip (click or `o`). `DailyBoardState::entry` (`BoardEntry`) records which: `q`/`Esc` restores the return screen, and reopens the modal for `Lobby` (one keypress per hop across matches) but not for `LoungeStrip`, where the modal was never open and the unseen-challenge glow stays. A backtick hop keeps the entry of the board it left. `BoardEntry::Practice` is the first-visit tour's pool table (`DailyState::open_practice_table`): an eight-ball rack built in memory with the viewer on the break, no `daily_matches` row, no events, no chat, never reloaded from the DB. Its rows reach the board down the same load channel a real reload uses, so the board code is unchanged; `practice_break` plays its one shot (the draft's opening aim at a fixed speed) on a blocking thread and sends the struck rack back the same way; that worker logs its own failure (`tracing::warn!`), since the tour gate holds the newcomer at the table until a break lands and nobody upstream would see it. Renders whichever game the match is; the screen title is "Daily Match".
- Leaving the board of a finished match you played acks its result (`DailyState::ack_finished_result`, fired from `close_board` AND from `open_board_inner` when hopping straight to another match). Conservative by design: if the final reload never landed (detail missing or still showing active), no ack, since the player never saw the result, so the row stays.
- Spectator mode (`DailyBoardState::spectating`, set in `open_board` when you're neither player): read-only. No cursor (every renderer gates the cursor on `my_turn`, which a spectator never is), the key-hint row shows `watching` instead of move/resign hints, and `board_resign` is a no-op. Live reload still fires (the reload keys purely on `board.match_id`), so a watched game updates move-by-move and shows the result overlay on finish. Chess renders in White orientation; connect four defaults a spectator to red's perspective. Battleship swaps its "their waters / your fleet" pair for two ships-hidden `spectate_waters_lines` grids (one per player, titled by name) that show only hits/misses: the fleets are never drawn, even on finish.
- Connect four layout: one centred grid (header letters, a `▼` indicator over the cursor column, ghost `◌` at the landing cell, drop count under the board), player bars showing disc colors, and a drop-history rail when wide enough. `arrows/wasd` slide the column cursor (the cursor IS a column index), `Space`/`Enter` drops (optimistic, `drop_in_flight` blocks a double drop until the reload), mouse drops via `target_geometry` (click maps to a column). The winning four render as solid tiles under the result overlay.
- Battleship layout: "their waters" target grid (left, cursor + fired shots; unfound enemy ships revealed as `░░` when the match ends) beside "your fleet" (right, ships + incoming fire), per-grid sunk/afloat summaries, player bars with afloat counts, and a salvo-history rail when wide enough. `arrows/wasd` aim, `Space`/`Enter` fires (optimistic, `shot_in_flight` blocks a double salvo until the reload), `r` resign, mouse fires via the render-recorded `target_geometry`.
- Backgammon layout: the classic two halves (point numbers in the viewer's own counting, home board bottom-right), checker stacks growing toward the middle, bar and off tray as first-class cursor columns, dice + hops-to-play in the middle gap. Lift/land with Space/Enter or clicks; the pending turn previews on the board and sends the moment it matches a complete legal turn.
- Vertical layout: the status line and the two player bars ride with the board as one centred group, so the colour/name labels always hug the board edges. The key-hint row is the exception and pins to the last row of the content column, with a `Min(0)` slack row absorbing the gap. Board sizing still reserves all four chrome rows (`CHROME_ROWS`), so pinning the hints does not change the tier the board picks.
- Loads the full row on open and on every `MovePlayed`/`ChallengeClaimed`/`MatchFinished` for the open match id (reload coalescing via `reload_pending`). Usernames are captured at open so names survive the match leaving the active snapshot on finish.
- Match chat pane: players (never spectators) with a `chat_room_id` get the embedded chat + voice strip below the board (same `EmbeddedRoomChatView`/`draw_embedded_room_chat` as the active room; the strip renders when the voice channel is enabled, `Ctrl+V`/`Ctrl+T` work unchanged). The slab takes a third of the height clamped to 9–13 rows and drops entirely under 27 rows; the board sizes itself in what remains. Keys mirror the active-room split: `i` composes, `j`/`k` select messages, message-action keys apply while a message is selected (`r` is reply then, resign otherwise), arrows belong to the board only while it's your move, Esc peels selection → board close. `` ` `` continues the lobby cycle from here.
- Move flow mirrors table chess: cursor + Space/Enter or mouse click, promotion defaults to queen, `r` resign (press twice), `p` toggles piece graphics. Castling takes either gesture, king first: onto your own rook (the cozy-chess encoding) or two squares toward it (lichess/chess.com); both land the same move and record identically, see `app/games/chess_core/CONTEXT.md`. In chess960 the two-square push exists only when the king started on e1/e8, so the rook gesture is the one that always works; the board's info rail carries that as the game's tagline. The rail is 22 columns wide and wraps, so its move-list budget counts the rows the header renders into, not its lines: budgeting by line lets a tagline wider than the rail push the newest move pair off the bottom. The optimistic move applies locally and reconciles on the next reload; legal moves are cleared until then so the cursor can't pick up opponent pieces.
- Piece-graphics image ids seed from `match_id` (the `placement_seed` param of `chess_core::board_ui`).
