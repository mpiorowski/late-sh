# Arcade games: per-game notes, controls, and adding a game

The Arcade's shape, cross-game invariants (daily rollover, board-date
stamping, telemetry), lifecycle and persistence are in `CONTEXT.md`. This file
holds what is particular to one game, the controls, and the checklist for a
new one.

## High-score games

- `twenty_forty_eight/`, `tetris/`, and `snake/` are high-score games. Snake's board glyph colors live in `ui.rs` (`glyph_color`), resolved per frame from `theme::` tokens and passed through `theme::legible_on_selection`: every cell is painted over `theme::BG_SELECTION()`, and twelve AMOLED palettes reuse an accent as that very fill (`success` on Greenery is byte-identical), so a raw token can render fg == bg. `snake/ui_test.rs` sweeps every palette asserting each glyph clears `theme::MIN_GLYPH_CONTRAST` against the fill. State carries only `ThingKind`; per-frame resolution also means a mid-level theme switch repaints glyphs together with the board.
- `traffic/` is a multi-track high-score game. Each track finish is graded to a normalized `0..=1000` score (`Track::grade_time`, from the track's theoretical fastest/slowest completion time, so every track yields a comparable range regardless of its distance/speed definition); crashing before the finish scores nothing. The user's Traffic high score is the **sum** of their per-track bests. Persistence keeps one best per `(user, track_key)` in `traffic_track_scores` plus a mirrored aggregate row in `traffic_high_scores` (`= SUM(track scores)`) so leaderboard queries stay uniform with the other high-score games. `track_key` is the `Track::name`.

## Daily puzzles

- `sudoku/`, `nonogram/`, `minesweeper/`, `solitaire/`, `le_word/`, `rubiks_cube/`, `sliding_puzzle/`, `netwalk/`, `chess_puzzle/`, `word_wheel/`, and `quartets/` are daily puzzle games. Le Word has a single global daily word rather than personal runs, Word Wheel a single global daily wheel and Quartets a single global daily wall. Rubik's Cube has one shared daily scramble and no personal mode. Sliding Puzzle pairs each deterministic UTC-daily difficulty with one saved random personal board. Its art is a gallery piece: `sliding_puzzle/art.rs` (pure) lays the day's piece over the board at the piece's own size (`art_grid`: tile = piece ÷ dimension, never under `MIN_ART_TILE_GEOMETRY` 6×3, the piece centred in blank cells, one span per cell, a wide glyph on a tile's last column blanked so no cut tears it) and `tile_fragment` cuts a tile out of it; `svc.rs::load_daily_art_task` claims the day's piece through `ArtboardPiece::feature_for_day` and decodes the canvas off the tick, owning the load's log line and `metrics::record_sliding_puzzle_art(SlidingPuzzleArtLoad)`; `state.rs` holds the `ArtSlot` (unrequested, loading, ready with a grid per difficulty, stale, refreshing, empty, failed with a 30s retry) that `poll_art` walks from `App::tick` while the board is the open screen, reset by the midnight rollover and re-asked by every open from the lobby (`open_daily`), so a mod's `/mod artboard feature` or removal shows without a reconnect; a piece already on the board stays up while the re-ask is in flight (stale, then refreshing), so an open never flashes numbered tiles, and a failed re-ask keeps it. The tip line shows the art status (loading, empty, failed, too wide) except while a two-press confirm is pending, which always wins. `ui.rs::add_art_tile_number` widens its overlay to a whole wide-glyph pair so the row keeps its width. No images, no downloads, no per-session caches worth releasing.
- `rubiks_cube/` is a daily deterministic puzzle game with a real cube state, face turns, a three-face angled render, and a compact net. It records one daily win per user/date, publishes Activity for the once-per-day base chip payout and Hub quest progress, and counts toward Arcade Wins. The in-progress cube persists per user in `rubiks_cube_games` (54-char sticker string + move count, saved fire-and-forget on every move/reset; rows from an older date are ignored on load since the daily scramble is deterministic). Reset (`0`) is a two-press confirm, and is refused outright once the cube is solved: the day's win is already banked, so re-scrambling would just put a finished puzzle back on the board.
- Sliding Puzzle draws its art at the piece's size, so **the tile geometry follows the piece, not the terminal**: `ui::board_layout` takes the art's tile size when the grid fits the board area and the numbered 7×3 grid otherwise, and the draw path and mouse hit-testing both go through it (`hit_test` takes `State::art_tile_geometry`) so a click lands on the tile the frame drew. A piece too big for the terminal says so on the tip line and plays numbered. The credit (`title by @painter`) sits on the row under the grid when there is one; the tip line stays the game's own messages. Faint amber tile numbers overlay the art while unsolved, since sparse ASCII tiles look alike. Tests build pieces from `dartboard_core::Canvas` directly, no network.
- `netwalk/` deals each board as a seeded spanning tree of the grid (`state.rs::generate`: randomized Prim from the centre source, every tile on the network, then each tile turned 0 to 3 quarters, re-rolled if that leaves it solved), easy/medium/hard 5x5/7x7/9x9, daily seeds from UTC date plus difficulty, personal seeds random, as Sliding Puzzle. Solved is "every tile lit from the source": turning keeps each tile's connection count, so a fully lit board has no loose end and any wiring that lights it wins, not only the generated one. `state_test.rs::the_daily_board_for_a_day_is_pinned` holds one day's board whole, since every saved board is rebuilt from its seed on load. A tile that looks the same every way round (`┼`) and a locked tile refuse a turn at no cost. The board draws at the largest tile size the terminal fits (`ui.rs::TILE_SIZES`: 5x3 with arms on all four sides and the source `■` and network ends `▣` marked, 3x1 with sideways arms, 1x1 the bare glyph); draw and `hit_test` share `board_layout`. Lit tiles `SUCCESS`, dark `TEXT_DIM`, the source `AMBER`, the cursor tile on `BG_SELECTION` through `theme::legible_on_selection` (swept on every palette in `ui_test.rs`), and a locked tile in heavy lines, so the lock reads without colour.
- `chess_puzzle/` plays Lichess puzzles from an embedded pack: `late-ssh/assets/chess_puzzles/{easy,medium,hard}.json`, 2,000 each, built by `late-core/src/bin/gen_chess_puzzles.rs` from the CC0 dump (rated 600 to 1100, 1300 to 1700, 1900 to 2300; popularity at least 90, at least 1,000 plays, rating deviation at most 80, at most four player moves, no underpromotion; a tier keeps the ids that hash lowest under a fixed seed, so the pick ignores the dump's row order). The pack types, the closed `Theme` set that names a puzzle (a mate count first, then the tactic) and the pick `choose_for_date` live in `late-core/src/chess_puzzle.rs`; `state.rs::pack` parses a tier once per process. The day's puzzles are claimed in the database like Quartets' wall, one row per tier in `chess_puzzle_daily_puzzles` (migration 269): `svc.rs::ensure_daily_puzzles` takes the advisory lock, picks a never-claimed puzzle of the tier by a hash of the date (the one claimed longest ago once the tier is used up, so a 2,000-puzzle tier runs five and a half years without a repeat) and hands the state a `Daily` of three pack puzzles; the session's first arrives with the bootstrap, and a board left without them (a failed load, or the rollover clearing yesterday's in `ensure_current_daily`) loads the next in the background through `arcade/daily_load.rs`; until it lands the daily boards are unavailable while personal puzzles still deal from the pack. Moves are stored in cozy-chess's spelling (a castle is the king taking its rook), so `state_test.rs::every_shipped_puzzle_replays_through_the_board` can hold every player move to exactly what `rules::legal_move_for` makes of its two squares. The opponent's setup move is on the board when it opens, drawn from the player's side; a right move waits `REPLY_DELAY_TICKS` (6 frames of the Arcade's 15 fps tick, `App::tick` calling `State::tick` while the board is open) before the reply lands. A wrong legal move is taken back and costs one of three lives; any checkmate wins, listed or not (a mate off the line ends the puzzle there, is the row's `mate_move`, and counts as the one move it was on the share card and on a restore); out of lives, the line still to play is named in the tip line and the side panel. Restart is personal-only: on a daily it would hand back spent lives, or replay a lost one with its solution shown. Pieces draw like a daily chess board's: PNGs where the terminal shows images (`ArcadeHubView::image_protocol` and the frame's `TerminalImageFrame` reach `ui.rs`), ASCII otherwise, `i` toggling (Sliding Puzzle's image key) for the session only, never saved; a solved or lost puzzle always draws ASCII (`State::board_render_mode`), since image pieces nobody re-pushes linger on protocols with no delete-by-id and the result overlay sits over the board. The board and the side panel share `ui.rs::layout` with `hit_test`. No red flash on a wrong move: the tip line names the move tried, which keeps `chess_core::board_ui` unchanged.
- `word_wheel/` is a word wheel: seven letters, a hub every word must use, words of four letters or more with letters repeating, one point per letter past three, doubled for a full wheel (a word using all seven). It is the genre's, not a copy of any one newspaper's game: the name, scoring, ranks and wheel drawing are its own. The pack is `late-ssh/assets/word_wheel/wheels.json`, 2,000 wheels built by `late-core/src/bin/gen_word_wheel.rs` from SCOWL `en_US` up to size 60 (no `s` among the letters, so plurals never pad a wheel and `s` stays the share key; 25 to 70 answers each, at least one full wheel; a blocklist of slurs and vulgar words; no two wheels share their letters). Each wheel stores its answers, so the runtime embeds no dictionary and "not in the word list" is a binary search. `late-core/src/word_wheel.rs` holds the pack type, the word rule (`fits`) the generator cuts by and `state_test.rs::every_shipped_wheel_holds_its_own_answers` holds the pack to, and the daily pick. Ranks (`state.rs::Rank`) are shares of the wheel's top score, rounded up: Bronze 20%, Silver 45%, Gold 70% are the easy, medium and hard wins, banked as the score crosses each (several at once if one word carries it past two), then Every word at 100%. Only the wheel's letters can be typed; another names itself in the tip line. `Tab` reorders the rim from a session counter, never saved.
- `quartets/` is a grouping wall: sixteen words hiding four quartets of four that share a link. It is the genre's, not a copy of any one newspaper's game: the name, the split, the strikes, the auto-locked last quartet and the look are its own. A try is four picked words; a quartet locks in as a bar with its link, and a miss is a strike that names its split (`state.rs::Split`: three and one, two pairs, one pair, all apart), more than a near-miss hint and the game's own clue. Three strikes end the wall and show the quartets not found as dim bars; once three quartets are in, the last four lock in by themselves, so a clean solve is three tries. A repeated try, or fewer than four picks, costs nothing. The pack is `late-ssh/assets/quartets/puzzles.json`, hand-written, no generator: `{ id, quartets: [{ link, words: [4] }; 4] }`, ids running from 1 so `find_puzzle` binary-searches them; `state_test.rs::every_shipped_puzzle_is_sixteen_distinct_words_in_four_quartets` holds it to sixteen distinct words of two to twelve lowercase letters and links of at most 28 characters that never name their own words. What the validator cannot check is that the partition is the only one: a word that fits two links must be forced by the other quartets, so read a new puzzle for that before adding it. Topping up is a JSON edit with the next id. Tiles size to the puzzle's longest word (10 to 16 cells); draw and `hit_test` share `ui.rs::layout`.
- **Solitaire's win cascade** (`solitaire/win_anim.rs`) is the classic finish: the moment the last card lands, the foundations throw themselves across the board a few cards a second, each one arcing off the floor and leaving its own art behind. It is pure (physics in board cells, card art stamped into a private character canvas) and area-independent: `ui.rs` records the board's drawn rect into `State::win_view` (a `Cell`, a render mirror and never a rule input) every frame, `App::tick` feeds that to `tick_win_animation` on the hot 15fps edge the Arcade already pays while a game is open, and `ui::draw_win_cascade` blits the canvas onto the frame buffer cell by cell so the board shows through the gaps. Foundations draw through `State::displayed_foundation_top`, which hides the cards already in the air. The cascade starts only on the first crossing into a win (a card pulled back off a full foundation and replayed, or the winning move undone and replayed, must not restart it), is cleared by `apply_snapshot` and `undo` so every new deal starts clean, and is not part of a snapshot: a won board reloaded from a save shows the result, not a replay. The `YOU WON!` overlay waits for the last card to land, and any key press or click runs the cascade out at once; other mouse traffic (a scroll, a drifting pointer, a button release) does not, so a mouse resting on the board cannot cut the finish short. The cursor fill (`ui::cursor`) is withheld while the cascade runs, so no amber slot sits under the flying cards.

## Share cards

- `share.rs` owns the share-card grammar: `ShareCard` (a header, at most eleven body rows, the fixed `ssh late.sh` footer), the closed `Glyph` set with its emoji and ASCII spellings, `render`, `title` (with or without a result), `arrow_row`, `half_block_picture`, `puzzle_number` (one count of days since `ARCADE_EPOCH` shared by every card, so all of a day's cards carry the same number; never move it: every pasted card would renumber), and the day card (one glyph per daily in lobby order, a row of one icon per daily beneath it so a reader can tell the boxes apart, plus the quest streak; `icon` is the exhaustive `DailyPuzzle` to emoji map). Each daily has a pure `share.rs` beside its `state.rs`: `is_ready` is the cheap gate the key line reads, `from_state` returns `None` until it holds (and always on personal boards), `card` takes plain data and is whole-state tested in `share_test.rs`. No card needs a legend: Le Word is the guess grid; Nonograms the finished picture in half-blocks (the solution, on purpose: the picture is the brag); Sudoku the 9x9 with clues white and the player's fills green, read straight from `fixed_mask`; Minesweeper the mine count plus the last ten clicks as safe/flag/boom, from the session-local `click_log` (empty on a board restored from a save); Solitaire the four foundation bars; Rubik's Cube and Sliding Puzzle are before-and-after, the day's scramble above an arrow row with the move count above the solved board, both derived from the puzzle date (`scrambled_stickers`, `generate_scramble` with the snapshot seed), with sliding tiles coloured by their home row; Netwalk is the day's scramble as a power map (green where the source already reached, dark where it did not) above the move count, with no after, since a solved board is all green; Chess Puzzle is one square per move the player found (green first try, yellow after a wrong move) and the theme's name, no squares or pieces, and a lost puzzle has no card; Word Wheel is the rank with the word and full-wheel counts, the score in ten squares (yellow per tenth of the top score), and a green square per full wheel, no letters or words, ready from Bronze. Quartets is the result in the title (`clean`, `N strikes`, or the quartets found out of four on a wall out of strikes) and one square per try in its split's colour, green a quartet, yellow three and one, blue two pairs, orange one pair, red all apart; the last four, which lock in by themselves, are no try. Copying, the banner, and the `share_cards_total` metric live in one place, `share_card` in `input.rs`, which reaches each game's card through the exhaustive `daily_share(app, puzzle)`; the metric's label is the roster key (`ShareCardKind::Daily(puzzle)`). `s` is intercepted there only while a card exists, so a Le Word letter keeps working on an open board.

## Controls

Root context keeps only global Arcade shortcuts. Keep detailed per-game control copy in each game's `ui.rs` info panel and in help modal copy.

Current per-game basics:
- 2048: `h/j/k/l` or arrows move, `r` restarts after game over.
- Lateris: left/right move, down soft-drops, up rotates, `Space` hard-drops, `c` holds the current piece, `p` pauses, `r` restarts.
- Snake: arrows or `h/j/k/l` steer, `p` pauses, `r` restarts.
- Sudoku: arrows or `h/j/k/l` move, `1-9` fill, `m` pencil mode, `u`/`U` undo (50-move queue, covering candidate mark edits), `0`/Backspace clear, `d/p/n` daily/personal/new, `[`/`]` difficulty.
- Nonograms: arrows or `h/j/k/l` move, `Space`/`x` toggle, `0`/Backspace/`c` clear, `d/p` daily/personal, `n` new board, `r` reset, `[`/`]` difficulty.
- Minesweeper: arrows or `h/j/k/l` move, reveal/flag/chord controls live in the game info panel.
- Solitaire: card/tableau/foundation controls live in the game info panel; mouse support maps left-click to select/place/draw stock, right-click to auto-move the clicked card, and wheel events over the board to tableau scroll.
- Le Word: type `a-z`, `Enter` submits, Backspace deletes, and `!` opens rules. A scored letter reads by shape as well as color (`ui.rs::score_tile`: correct is a solid tile, present a solid tile in brackets, absent the bare letter), because many themes give `SUCCESS`, `AMBER`, and `TEXT_FAINT` the same value; the rules legend draws the same tiles instead of naming colors.
- Rubik's Cube: everyone gets the same UTC daily scramble; `u/d/l/r/f/b` turns faces clockwise, uppercase turns inverse, `0` resets today's scramble (`s` is the share card, like every daily), `v` rotates the view right, and arrows rotate the view in their own directions.
- Sliding Puzzle: arrows or `h/j/k/l` slide an adjacent tile in the indicated direction into the gap; left-clicking an adjacent tile moves it directly. `i` toggles the session-only numbered/art view without changing the board or reward contract; on a failed art load, `i` twice asks again at once. `d`/`p` switch daily/personal mode, `n` twice starts a new personal board, `[`/`]` changes difficulty, and `r`/`0` twice restores the active scramble. Personal boards persist but have no reward. Reset is refused on a solved daily (the win is banked), like Rubik's Cube. Sliding Puzzle has no keypress-time rollover: a board left open across UTC midnight finishes under its own date and `refresh_daily_games` rolls it once the player looks away.
- Netwalk: arrows or `h/j/k/l` move the cursor, `Space`/`Enter` turn the tile clockwise, `x` counter-clockwise, `f` locks or unlocks it, a left click turns the clicked tile. `d`/`p`, `n` twice, `[`/`]` and `r`/`0` twice as Sliding Puzzle, reset refused on a solved daily, and no keypress-time rollover.
- Chess Puzzle: arrows or `h/j/k/l` move the cursor on screen, `Space`/`Enter` pick up the player's piece, put it back, or play it (the move is tried before a pick-up, so the king onto its rook castles), a left click does the same on the clicked square. `d`/`p`, `n` twice and `[`/`]` as Sliding Puzzle; `i` toggles PNG and ASCII pieces, as it toggles Sliding Puzzle's art (daily chess's `p` here picks the personal board); `r`/`0` twice restarts a personal puzzle and is refused on a daily.
- Word Wheel: type `a-z` (only the wheel's letters go in; `q` is a letter, so `Esc` leaves), `Enter` submits, Backspace deletes, `Tab` shuffles the rim, `!` opens rules, a left click on a wheel letter types it. No reset: the wheel is the day's, and found words stay found.
- Quartets: arrows or `h/j/k/l` move, `Space` picks or unpicks the word, `Enter` tries the four picked, `x` clears the picks, `Tab` shuffles the words left, `!` opens rules, a left click picks a word. No reset: tries are the day's, strikes included.

Destructive daily/personal puzzle reset keys use a local confirmation flag. Sudoku (`n`/`r`), Nonograms (`n`/`r`), Minesweeper (`n`), Solitaire (`n`/`r`), Rubik's Cube (`0`), Sliding Puzzle and Netwalk (`n`/`r`/`0`), and Chess Puzzle (`n`, and `r`/`0` on a personal puzzle) set `reset_pending` on the first press and reset only on a repeated matching action key. Any ordinary movement, mode/difficulty switch, board edit, card action, face turn, or view change clears the pending flag. Renderers surface a short "press again" tip while pending.

## Adding a new Arcade game

Decide the category first. High-score games behave like `tetris/`, `twenty_forty_eight/`, and `snake/`: one saved run, one all-time high-score row, and final score events for monthly Hub boards. Daily/personal puzzle games behave like `sudoku/`, `nonogram/`, `minesweeper/`, and `solitaire/`: one daily puzzle plus optional personal runs, daily win records, chip bonus, and Activity event. Le Word, Rubik's Cube, Word Wheel and Quartets are the same daily-win/reward/activity pattern with shared UTC puzzles and no personal mode.

Expected source shape:
- `late-ssh/src/app/arcade/<game>/mod.rs` declares only local modules.
- `state.rs` owns per-session state and pure rules.
- `input.rs` owns key routing for that game.
- `ui.rs` renders the game and its local help/status panel.
- `svc.rs` owns async tasks and calls `late-core` model APIs. Keep SQL in `late-core`, not in `late-ssh`.

Core model/persistence work:
- Add `late-core/src/models/<game>.rs` for DB-backed state/high-score/win models.
- Add a migration under `late-core/migrations/`.
- Add the model module to `late-core/src/models/mod.rs`.
- For high-score games, expose `HighScore::update_score_if_higher` and `HighScore::record_score_event`.
- For daily games, follow the existing daily-win model pattern and keep one completion fact per user/date/difficulty or pack.

Wiring, a daily puzzle: add the variant to `roster!(DailyPuzzle: ...)` in `late-core/src/models/leaderboard.rs` at its place in the lobby order (the roster is the lobby, the day card, the backtick cycle and the rollover; nothing else lists games) and fix the red, in this order so each fix unlocks the next:
- `late-core`: the roster's `key`, `title`, `tiers`, `wins_table`; the model file and its migration, whose win insert composes `bump_daily_win_total_sql`.
- `late-web`: the paper's front-page card art, `late-web/src/pages/paper/arcade_art.rs::art`.
- `late-ssh`: `pub mod <game>;` in `arcade/mod.rs`, the `ActivityGame` variant and its maps (`key`, `label`, `family`, `daily_puzzle`, the lounge arm in `activity/filter.rs`, the `metrics.rs` labels), `daily::activity_game`, `share::icon`, the per-puzzle matches in `arcade/` (`input.rs`, `ui.rs`, `daily.rs`, the Arcade arm in `app/tick.rs`), the workspace leg (`app/workspace/arcade.rs`), the `App` state field, the service in `late-ssh/src/state.rs` and `main.rs`, and the saved-game load in `session_bootstrap.rs`/`ssh.rs`.

Then what the compiler cannot see, each held by a test:
- the `reward_templates` rows in the migration, one per tier of `tiers()` at that tier's `Difficulty::chips` (`late-core/src/models/reward_test.rs::every_daily_tier_has_an_active_template_paying_its_tier`);
- the win bump (`late-core/src/models/leaderboard_test.rs::every_daily_win_insert_bumps_the_all_time_rollup_once`, whose `record_daily_win` match is red in the test build until the new model is called);
- a splash tip naming the game (`common/splash_tips_test.rs::every_daily_puzzle_has_a_tip`);
- the quest templates, `is_quest = true` rows in the migration that put the game in the Hub quest pool at the tier pattern and amounts in `app/hub/CONTEXT.md`, Quests (`late-core/src/models/quest_test.rs::every_daily_puzzle_has_an_active_quest_template`).

Then the prose: the help modal's Arcade notes and controls (`app/help_modal/data.rs`; its payout and Arcade Wins lists are generated from the roster), this file, `CONTEXT.md` here and at the root, and `LICENSING.md` when the game ships imported data.

Wiring, a score game: add the variant to `roster!(ScoreGame: ...)` at its lobby place and fix the red the same way (the roster's methods, the card art, `ActivityGame`, `ui.rs::game_for_selection`, the key/arrow/draw dispatch and lobby card, the Arcade arm in `app/tick.rs`, the state field, service and saved-game load). Help-modal copy and the docs above as for a daily.

Leaderboard/Hub checklist:
- High-score games must write final score events through a `late-core` model method so monthly boards do not depend only on legacy high-score table `updated` timestamps. Lateris and Snake also publish hidden quest Activity score events on final score submission; Snake includes the reached level for weekly/daily quest matching.
- A restored run that was already over must not emit its final score event again (it fired when the run ended). A second emission is a fresh `GameScored` activity, which completes score-based daily quests for a game nobody played; `snake/state.rs` carries `score_event_recorded` across `restore` for this.
- The roster variant above is also the leaderboard enrollment: a `DailyPuzzle` variant joins the per-game win boards, Arcade Wins points, today's champions, and daily statuses at once; a `ScoreGame` variant joins its monthly/all-time score boards. The Leaderboards page (`app/leaderboard/`) picks the board up from the roster with no page change.

Testing guidance:
- Pure rules and key-routing helpers get inline unit tests in `state.rs` or `input.rs`.
- DB/service coverage lives in the adjacent `svc_test.rs` beside each game's `svc.rs` (wired with `#[cfg(test)] mod svc_test;`), using `crate::test_helpers::new_test_db`.
- Agents run targeted tests through `make test-llm ARGS="-p late-ssh --lib -E 'test(arcade)'"`; `make check` stays with the human owner.
