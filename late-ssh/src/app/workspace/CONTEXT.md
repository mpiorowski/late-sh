# Workspace Context

## Metadata
- Scope: `late-ssh/src/app/workspace`, the backtick workspace cycle: the one key that hops Home chat, your-turn daily boards, seated house tables, unfinished Arcade dailies, and live door games.
- Last updated: 2026-09-01 (domain created: the cycle moved out of `lobby/workspace.rs`, the Arcade leg moved in from `arcade/workspace.rs` (non-cycle residents stayed behind as `arcade/daily.rs`), and the door leg's liveness moved down to the door domain: `door/hub/state.rs::HubGame::live_screen` is the one definition the cycle and the sidebar pips both read, `live_doors` the ordered list)
- Parent context: root `CONTEXT.md`. The legs' own domains: `lobby/daily/CONTEXT.md`, `lobby/house/CONTEXT.md`, `arcade/CONTEXT.md`, and the per-door contexts under `door/` (e.g. `door/darkroom/CONTEXT.md`, `door/nethack/CONTEXT.md`).
- Status: Active

## 1. Shape

The cycle is its own vertical slice because it spans four domains and belongs to none of them. It consumes each leg through that domain's own queries (`DailyState::my_turn_matches`, `HouseState::my_seated_tables`, `door::hub::state::live_doors`) and owns everything cycle-specific itself: the leg order, the `GameWorkspace` enum, the routing, and the Arcade stop machinery (`ArcadeStop` is cycle vocabulary, not an Arcade concept; the Arcade never uses it). Adding a game to the cycle is an edit to this domain, on purpose: what joins and in what order is one policy, auditable here.

Stop order: Home chat → each daily board waiting on your move (nearest deadline first) → each house table you hold a seat at (roster order) → each unfinished Arcade daily (lobby order) → each live door game (hub sidebar order) → back to Home. Rooms are gone; real-time Arcade games (Lateris, Snake, Traffic, NES) and personal boards never join.

## 2. Module map

| File | Responsibility |
|---|---|
| `mod.rs` | Declarations only. |
| `cycle.rs` | The cycle itself (`GameWorkspace`, `cycle_game_workspace`, pure `next_workspace` + its unit tests in `cycle_test.rs`). Hopping out of an Arcade stop clears `is_playing_game` (boards save move-by-move, nothing else to close); hopping preserves the first stop's `return_screen` (Arcade stops don't record one, so a chain passing through resumes with `Screen::Arcade`), and the wrap back to Home skips the modal (`board_input::leave_board` / `house::input::leave_table`). The final leg is `GameWorkspace::Door`: `door::hub::state::live_doors` (the door games with a live session, sidebar order), with the three liveness models defined once on `HubGame::live_screen`, which the hub's in-progress pips read too (precomputed at the top of `App::render`), so the cycle and the pips cannot drift. Lateania first: it has no detached session (`set_screen` away tears the world session down with an autosave), so its stop is the recency window `App::lateania_detached_at`, armed only by the in-world backtick detach (`lateania/input.rs` returns `InputAction::Detach`, mapped in `lateania/screen.rs`), cleared by an explicit Esc-Esc leave or slot delete, checked via `App::lateania_recently_active` (5 min); hopping in calls `enter_lateania()` to re-join the remembered slot, skipping character select. Then the roguelikes (NetHack/DCSS/Brogue) with a running (detached) game; inside one of those ` is intercepted by `App::handle_input` and re-enters this cycle as a detach (the running door state survives `set_screen`), so hopping in is a plain screen switch and the same key hops onward or out. Last, the two native remakes (Dark Room, Green Dragon): their state also survives `set_screen` (they tick off-screen by design), so being loaded is the whole test, hopping in is a plain screen switch too, and nothing is armed on the way out. Green Dragon refuses the hop mid-fight (leaving a fight is never free, and the reap would erase the session-only encounter), Dark Room mid-ascent. What ends their visit is the idle deadline `door::game::IDLE_WINDOW` (30 min away from that door: no key in it, and it not the open screen, since `App::tick` stamps presence while it is): `App::tick` reaps them with `save_on_leave()` + `leave_*()`, exactly what an explicit Esc does, which drops them off this cycle and off the hub's in-progress pips. Never while the door is the open screen, so reading on it is not being away. Dark Room loses no credit to the reap: the leave stamps `last_settled`, and re-joining later in the same SSH session credits the gap in one burst (`darkroom/sim.rs::settle`). |
| `arcade.rs` | The Arcade leg: `ArcadeStop` closed enum (the seven daily puzzle games in lobby order), `active_daily_stop` (the stop for the active board, `None` for personal/practice boards), `unfinished_daily_stops` (today's daily boards with at least one player move and no win; each game state exposes `first_unfinished_daily()` / `has_unfinished_daily()`), and `open_stop` (points the Arcade at the right daily board and sets `is_playing_game`). The Arcade's non-cycle daily lifecycle (`SessionDailyWins`, the midnight `refresh_daily_games` rollover) stays in `arcade/daily.rs`. |

## 3. Invariants

- The key binding stays with its screens: `dashboard/input.rs` keeps only the binding; `arcade/input.rs` routes backtick out of active daily puzzles; the doors intercept it in their own input paths and re-enter the cycle as a detach.
- This domain reads other domains through their queries and open/enter functions, never their internals. Each leg's membership test lives with the leg's domain (`my_turn_matches`, `my_seated_tables`, `has_unfinished_daily`, `HubGame::live_screen`); this domain owns only the leg order and the routing.
- New workspace kinds go through the `GameWorkspace` enum; do not re-add rooms stops.
